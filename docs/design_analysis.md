# تحليل التصميم وتفكيك فكرة التطبيق

## 1. لمحة عامة عن الهوية البصرية
- يعتمد التصميم على تدرجات باستيل دافئة (أخضر فاتح، بنفسجي، وردي، بيج) مع مساحات بيضاء واسعة وحدود ناعمة بزوايا مستديرة جدًا.
- يوجد تباين واضح بين الخلفية العامة الأفتح والبطاقات الملونة التي تحوي المحتوى الأساسي.
- الرموز تعتمد أسلوبًا خطيًا بسيطًا يتماشى مع مكتبة Iconly، مع استخدام صور ملف شخصي دائرية ودوائر شبه شفافة لتأطير الأزرار العائمة.
- الخط المستخدم ذو طابع عصري وودود مع وزن متوسط للعناوين ووزن عادي للنصوص، ما يلائم Google Fonts مثل "Cairo" أو "Nunito".

## 2. بنية الواجهات في الصور المرجعية
1. **شاشة ترحيب/لوحة معلومات**
   - شريط علوي يحوي صورة المستخدم، تحية باسم المستخدم، وأزرار سريعة للوصول إلى التنبيهات والإعدادات.
   - مقطع خطوات onboarding على شكل بطاقات أفقية قابلة للتمرير تعرض حالة الإكمال بالنسبة المئوية.
   - بطاقات معلومات مالية (المصاريف، المدفوعات، رصيد المحفظة) مع أزرار أفعال سريعة (إرسال الأموال، طلب الأموال).
   - قسم لحسابات العائلة مع تفاصيل مختصرة وأزرار إرسال الأموال.
   - شريط تنقل سفلي بأيقونات واضحة وزر مركزي بارز.

2. **شاشة ملخص المدفوعات**
   - بطاقات مقسمة إلى أعمدة لكل نوع من البيانات (الإنفاق، المدفوعات، الموقع).
   - استخدام تدرج لوني مختلف لكل بطاقة مع أيقونة صغيرة في العنوان وزر ثانوي داخل البطاقة.
   - وجود زر عائم علوي (إرسال الأموال) مع مؤشر الموقع وإحصائيات قصيرة.

3. **شاشة المحفظة والحسابات**
   - رأسية تحتوي على رصيد المحفظة مع أزرار "إضافة أموال"، "إرسال أموال".
   - أقسام منفصلة للحسابات المرتبطة وأفراد العائلة، كل قسم عبارة عن بطاقة بداخلها عناصر متعددة منظمة عموديًا.
   - المحافظة على نفس أسلوب الهوية البصرية وزوايا الانحناء.

## 3. الانعكاسات على التطبيق المقترح
- يجب توفير نظام ألوان ديناميكي يسمح للمستخدم بتغيير اللون الأساسي مع المحافظة على البطاقات اللونية المساعدة.
- التطبيق يعتمد بشكل كبير على البطاقات، لذلك نحتاج إلى Widgets مكررة قابلة لإعادة الاستخدام مع دعم الأنماط الفاتحة والداكنة.
- الأنيميشن عنصر رئيسي (انتقالات ناعمة، تحريك للبطاقات عند التمرير، تأثيرات parallax بسيطة) ويجب استخدام `AnimatedSwitcher` و`AnimatedPositioned` و`AnimationController` من Flutter animation.
- بسبب كثرة البيانات، يجب توفير آليات تصفية، مقارنة، بحث، وسياق حواري يظهر التفاصيل الكاملة عند الضغط على العناصر.
- بما أن الصور تعرض إدارة مالية عائلية، يمكن تعميم التطبيق إلى منصة لإدارة محافظ عائلية مع خصائص تتبع المصروفات، إرسال الأموال، ومقارنة خطط الإنفاق.

## 4. متطلبات الصفحات والويجت
- **الصفحات الأساسية**: Onboarding قصصي، تسجيل الدخول/إنشاء حساب/استرجاع كلمة المرور/تسجيل الضيف، لوحة تحكم رئيسية، إدارة الحسابات والمحافظ، صفحة تفصيل عنصر (بطاقة/عضو)، كتالوج العناصر مع فلترة ومقارنة، صفحة الإعدادات (تخصيص الألوان والوضع الداكن، اللغة)، صفحة المساعدة مع زر الذكاء الاصطناعي، صفحة الإشعارات، صفحة الملف الشخصي.
- **الويجت المشتركة**: شريط تنقل سفلي ديناميكي، شريط علوي قابل للتخصيص، بطاقات بيانات متعددة الأحجام، عناصر قائمة مع مؤشرات قوة/حالة، 3D Hero Viewer يعرض صورة العنصر باستخدام تحويل ثلاثي الأبعاد، عناصر Skeleton لانتظار التحميل، مربعات مقارنة قابلة للتحديد، مربعات حوار منبثقة للشرح.
- **التقنيات**: اعتماد `StreamBuilder` و`ValueListenableBuilder` للتحكم في إعادة بناء الأجزاء، استخدام `RefreshIndicator` للسحب للتحديث، بناء نظام Pagination داخلي باستخدام `ScrollController` و`Future`، الحفاظ على الحالة محليًا بواسطة `shared_preferences`, دعم لغتين عبر `flutter_localizations` وتوفير ملفات ترجمة AR/EN.

## 5. اعتبارات تجربة المستخدم
- إبراز أزرار الدعوة للإجراء باستخدام لون أساسي قابل للتخصيص مع ظلال خافتة.
- توفير حالة مرئية لقوة كلمة السر، ومؤشرات إكمال المهام، وحالات ف empty/error عبر Skeleton وAnimatedOpacity.
- ضمان استجابة كاملة للشاشات المختلفة باستخدام `LayoutBuilder` و`MediaQuery` لضبط حجم البطاقات وشكل الشبكات.
- اعتماد NetworkImage مع معالجة أخطاء التحميل وإظهار Placeholder Skeleton قبل عرض الصور.

هذا التحليل يشكل القاعدة لإنشاء Prompt JSON تفصيلي يوجّه Codex لبناء التطبيق وفقًا للاشتراطات المحددة.
